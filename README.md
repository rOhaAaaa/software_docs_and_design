# Лабораторна робота №2: Реалізація серверної частини аплікації

**Варіант:** 21 | **Тема:** Booking.com (Backend & ORM)

## Завдання

1. Реалізувати серверну частину застосунку з використанням трирівневої архітектури (DAL, BLL, PL).
2. Забезпечити зв'язок між рівнями через абстрактні інтерфейси та шаблони Inversion of Control (IoC) / Dependency Injection (DI).
3. Використати SQLAlchemy ORM для мапінгу об'єктів у базу даних SQLite згідно з UML-діаграмою класів із Лаби №1.б.
4. Створити CLI-генератор для створення масиву даних (мінімум 1000 рядків) у єдиному форматі CSV.
5. Реалізувати бізнес-логіку зчитування та імпорту даних із CSV-файлу в реляційну базу даних з дотриманням цілісності зв'язків.

---

## Архітектура системи

Проєкт побудований на принципах чистої архітектури (Clean Architecture), де кожен шар має чітку зону відповідальності:

* **DAL (Data Access Layer):** Відповідає за взаємодію з SQLite та читання сирих даних із CSV. Використовує патерн `Repository`.
* **BLL (Business Logic Layer):** Містить сервіси для обробки даних, мапінгу "пласких" рядків у складні ORM-моделі та управління транзакціями. Не залежить від конкретної БД.
* **PL (Presentation Layer):** На даному етапі представлений абстрактними інтерфейсами (`IView`), які описують майбутній UI (Console/Web).
* **Core:** Містить централізовану конфігурацію проєкту та налаштування IoC-контейнера (`dependency-injector`).

## Структура проєкту

```text

├── src/
│   ├── dal/            # Моделі SQLAlchemy, Repository та Інтерфейси DAL
│   ├── bll/            # Бізнес-логіка та сервіси (DataImportService)
│   ├── pl/             # Інтерфейси презентаційного рівня (IView)
│   ├── core/           # Конфігурація підключення до БД (Config)
│   └── generator/      # CLI інструмент для генерації Faker-даних
├── data/               # Згенерований CSV файл та база SQLite
├── screenshots/        # Скріншоти демонстрації роботи
├── main.py             # Точка входу (Налаштування DI Container та запуск)
├── verify_db.py        # Скрипт верифікації даних у базі
└── requirements.txt    # Залежності
```

## Реалізація моделей

Моделі в коді повністю відповідають UML-діаграмі класів. Реалізовано:

- **Успадкування:** використано `Joined Table Inheritance` для типів додатків та користувачів.
- **Поліморфізм:** перевизначення методу `download_app()` для різних типів контенту.
- **Зв'язки між моделями:**
  - One-to-Many (Category → Apps)
  - Many-to-One (App → Developer)
  - Composition (App → Versions, Reviews)

## Як запустити

### 1. Підготовка середовища

```bash
# Створення віртуального середовища
python -m venv venv

# Активація (Windows)
venv\Scripts\activate

# Встановлення залежностей
pip install -r requirements.txt
```

### 2. Генерація даних (1000+ рядків)

```bash
python src/generator/cli_gen.py --count 1050
```

### 3. Запуск імпорту та бізнес-логіки

```bash
python main.py
```

### 4. Перевірка бази даних

```bash
python verify_db.py
```
