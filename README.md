# Лабораторна робота №4: Патерн "Стратегія" (Strategy)

Цей проєкт реалізує архітектурний шаблон проєктування **Strategy (Стратегія)** (з групи GoF) для гнучкого управління виводом даних. 

Програма вичитує дані з датасету **"Chicago Crimes"** (у форматі CSV) і може направляти їх у різні сховища (Консоль, Redis, Kafka) без зміни основного коду програми, спираючись виключно на конфігураційний файл.

## 🚀 Основний функціонал та Патерни
- **Патерн "Стратегія":** Логіка виводу інкапсульована в окремі класи (`ConsoleStrategy`, `RedisStrategy`, `KafkaStrategy`), які реалізують спільний інтерфейс `IOutputStrategy`.
- **Розділення відповідальності (SRP):** Код, який вичитує дані з файлу (`data_reader.py`), повністю відділений від коду, який відповідає за їхній вивід (`strategies.py`).
- **Динамічна конфігурація:** Перемикання між цільовими системами виводу відбувається "на льоту" шляхом зміни параметра `output_strategy` у файлі `config.json`.

## 🏗 Структура проєкту
- `main.py` — Точка входу та клас-Контекст (`DataProcessor`), який делегує роботу обраній стратегії.
- `strategies.py` — Інтерфейс та конкретні реалізації стратегій виводу.
- `data_reader.py` — Клас `CsvReader` для читання та парсингу набору даних про злочини.
- `config.json` — Файл налаштувань для вибору стратегії та вказання параметрів підключення до баз даних.
- `data/crimes.csv` — Фрагмент відкритого датасету Chicago Crimes.
